# Build and local packaging

Run root `build.bat -QtRoot <Qt-6.8.3-msvc2022_64> -Silent`. The explicit Qt root or `MATERIAL_COMPANION_QT_ROOT` is read-only. The build discovers installed MSVC through official `vswhere`, invokes CMake/Ninja, copies the required Qt modules and SQLite plugin, and bundles available MSVC CRT files. The core, service, host and local contract executable are genuine C++ binaries. Desktop CMake is included when present; absence is reported explicitly. The receipt records source commit, local tracked changes, executable hashes and time. Tests are not automatically invoked by build or packaging.

`build-installer.bat` invokes the exact root build and uses pinned NuGet 6.11.1 and Squirrel.Windows 2.0.1. Optional `-NugetPath` and `-SquirrelPath` reuse caller-selected caches read-only. Default NuGet acquisition uses the official versioned HTTPS distribution and requires a valid signature. Squirrel acquisition uses its pinned official NuGet package. Output is genuine unsigned `Setup.exe`, `RELEASES` and full package, plus any delta produced by Squirrel. The source-bound receipt reports hashes and sizes. No script publishes, tags or uploads anything.

This package currently contains native service and messaging host only, with no desktop shell or native-host registration. Installation/runtime acceptance is not verified. Unsigned output may trigger unknown-publisher or SmartScreen warnings. Existing-machine build success does not prove a fresh installation. Automatic Qt/MSVC/CMake/Ninja fresh-machine acquisition is incomplete and fails with an explicit missing-tool reason rather than claiming bootstrap success. Required elevation/licensing remain user-controlled.
