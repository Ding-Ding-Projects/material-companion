# Build and local packaging

Run root `build.bat -QtRoot <Qt-6.8.3-msvc2022_64> -Silent`. The explicit Qt root or `MATERIAL_COMPANION_QT_ROOT` is read-only. The build discovers installed MSVC through official `vswhere`, invokes CMake/Ninja, copies the required Qt modules and SQLite plugin, and bundles available MSVC CRT files. The core, service, host and local contract executable are genuine C++ binaries. Desktop CMake is included when present; absence is reported explicitly. `-DesktopTests` enables `COMPANION_DESKTOP_TESTS=ON` for the separate desktop target. Available desktop builds receive Qt runtime DLLs, QML modules and platform plugins from the supplied read-only cache.

Before production, the build captures the source commit, symbolic ref, local changes and every tracked/nonignored input hash. By default local changes are rejected; `-AllowDirtySource` explicitly records their exact inputs instead. Production succeeds only when a second snapshot matches the original revision, ref, changes and hashes. The build receipt uses the original snapshot, not a sampled completion-time HEAD. Packaging captures its own original snapshot, embeds the original build receipt in its payload and packaging receipt, and checks source stability again. Tests are not automatically invoked by build or packaging.

`build-installer.bat` invokes the exact root build and uses pinned NuGet 6.11.1 and Squirrel.Windows 2.0.1. Optional `-NugetPath` and `-SquirrelPath` reuse caller-selected caches read-only. Default NuGet acquisition uses the official versioned HTTPS distribution and requires a valid signature. Squirrel acquisition uses its pinned official NuGet package. Output is genuine unsigned `Setup.exe`, `RELEASES` and full package, plus any delta produced by Squirrel. The source-bound receipt reports hashes and sizes. No script publishes, tags or uploads anything.

This package currently contains native service and messaging host only, with no desktop shell or native-host registration. Installation/runtime acceptance is not verified. Unsigned output may trigger unknown-publisher or SmartScreen warnings. Existing-machine build success does not prove a fresh installation. MSVC/CMake/Ninja fresh-machine acquisition remains incomplete and fails with an explicit missing-tool reason rather than claiming bootstrap success. Required elevation/licensing remain user-controlled.

## Pinned Qt acquisition

An absent or insufficient selected Qt cache triggers `scripts/ensure-qt.ps1`, which acquires a complete project-owned Qt 6.8.3 MSVC2022 cache under the current user's local application data. It does not modify caller-supplied caches. The reviewed `qt683-manifest.json` pins the official Qt repository metadata SHA-256, exact package version and official SHA-1 checksum of each archive. The bootstrap additionally records each archive SHA-256. These hashes prove matching reviewed downloads, not a signature or protection against a compromised official source.

The eight official archives provide Qt Base, SVG, Declarative/Quick/QuickControls2, Tools, Translations, D3D/software rendering and Shader Tools. Existing operating-system `tar` supports their 7-Zip format, so no additional extractor is installed. Member paths are checked for absolute/traversal forms and links are rejected before extraction. Extraction occurs in an owned stage, required modules are read back, every installed file is SHA-256 inventoried, and only the verified completed cache is promoted. A relative `bin/qt.conf` makes the acquired tools independent of another product's installation path. A warm reuse verifies the complete file inventory and every hash; a changed cache is rejected rather than silently trusted or overwritten.

Local bootstrap checks cover traversal paths, changed modules, added files and version mismatch. The real official archive acquisition and warm validation were run on the existing machine; a genuine fresh environment remains unverified. See the [official Qt repository](https://download.qt.io/online/qtsdkrepository/windows_x86/desktop/qt6_683/qt6_683/) and [Qt deployment documentation](https://doc.qt.io/qt-6.8/windows-deployment.html).
