## Layout and visual contract

Use a restrained blue/teal Material Design 3 palette, quiet surface containers, clear text contrast, rounded button geometry and generous but purposeful reading space. Primary content is article navigation and truthful evidence. Do not substitute decorative metrics, mock product captures, sample project records or fake progress.

At 1440 pixels, use a 256-pixel left navigation region and spacious reading surface with approximately 64-pixel inner margins. At 1280, use a 236-pixel navigation region and approximately 48-pixel content margins. Below 1050, collapse secondary article columns. Below 700, turn the default side strip into a bounded edge/tab affordance without truncating labels; internal overflow is allowed in the tab strip, never on the page body. At 320, stack actions and allow bilingual labels to wrap. Treat the reference's narrow horizontal strip as a design fallback requiring full production docking behavior, not an exemption from the default-left tab contract.

Use a registered component inventory for every owned control and layout surface. Implement buttons, fields, switches, sliders, menus and selectors through locally bundled official Material Web components. Specification-backed compositions cover reading surfaces, tab management, status rows, article lists, dialogs and inspectors where no single official primitive is sufficient. Register the complete anatomy and state behavior; do not wrap an unreviewed generic placeholder and call it compliant. Functional data colors never become a blanket exception for chrome.

Typography must support English and Hong Kong Cantonese. Prototype fonts use platform fallbacks only. Production font choice remains an explicit asset task: acquire complete licensed fonts through a reproducible script, preserve weights and Unicode ranges, record byte hashes, bundle locally, and verify the actual rendered font at required weights and scripts. No CDN or remote font is allowed.

## Visitor state and privacy

Maintain separate versioned stores for ordinary visitor preferences, tab/group state, redacted history, notifications, and any private validated wording cache. Never place private file values or source-file metadata in URLs, DOM belonging to an integrated page, adapter messages, postMessage payloads, native requests, analytics, logs, exports, history, clipboard or public source. Do not automatically apply extension-owned vocabulary to website DOM. A website-owned local loader, when authorized and implemented, affects only its own visitor presentation.

All public unauthenticated content ships ordinary language. A private wording unlock must satisfy the actual authenticated local presentation boundary; a selected file or client-only checkbox is not invented server authentication. If the static host cannot provide the required authenticated boundary, explicitly record the limitation and keep original wording rather than leaking terms or falsely claiming authentication. The generic local-file control and its unavailable reason remain visible where required.

The loader schema is versioned, bounded to 256 KiB UTF-8, depth 8, keys to 160 code points and values to 1,000 code points, with a dynamic entry inventory and no hardcoded entry-count ceiling. Reject malformed input, duplicate keys, unknown versions, unsafe keys and invalid fields before any partial application. Validate cache on load, preserve the last valid selection after invalid replacement, and purge private cache on explicit clear. Do not store original path or filename. Test only neutral payloads in public source and captures.

Per-visitor toy locks are user-experience controls, not security. Browser storage and its reset semantics must be disclosed. Lack of an operating-system credential vault cannot be hidden. Credentials and private records never enter generic preference export/history. School-mode cross-application synchronization requires a real authorized bridge; a static page cannot claim it from isolated localStorage.

## Accessibility, focus and motion implementation

Provide skip link, header/navigation/main/footer landmarks and one coherent heading hierarchy. Navigation uses real tab roles and orientation-aware roving focus; activate with Enter/Space and arrows as documented. At narrow widths update orientation semantics with geometry. Article anchors focus the target heading and preserve URL. Menus expose exact keyboard shortcuts and close to their origin. Touch has equivalents for hover/context actions. Focus must remain visible over all themes and custom styles.

Controls have minimum 44 CSS-pixel interaction areas where applicable. Bilingual content places a readable secondary line instead of fixed-height truncation. Announce result changes, not every rendering tick. Theme and language controls have correct current values and fully localized accessible labels. Honor browser text scaling and operating-system reduced motion. Ordinary transitions are 120-200ms state-layer changes; reduced motion removes travel and automatic cycling without removing information.
